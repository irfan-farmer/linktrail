# LinkTrail

**Never lose a tab again, privately.** LinkTrail keeps a searchable history of
every link you've had open, so you can find and reopen it later. It runs
entirely on your device.

> 🔒 **Stays on your device.** No servers, no accounts, no analytics, no network
> requests. Addresses are saved without query strings by default, and private
> windows are never recorded. See [PRIVACY.md](PRIVACY.md), including what it
> *can* still reveal, and check it against the source.

## Why you can trust it

- **It can't phone home.** There is no network code anywhere in the source. It
  requests no host permissions, so it can't read the contents of your pages, only
  tab titles and addresses.
- **Private browsing stays private.** The manifest blocks the extension from
  incognito/private windows, and the code skips private tabs as a backup.
- **Risky parts are removed.** Query strings, fragments, and embedded
  credentials are stripped before storage unless you opt in to full addresses.
  Titles can be switched off.
- **Your settings apply to saved data too.** Excluding a site or switching off
  titles/full addresses also cleans up data that was already saved.
- **Deleting really deletes.** Deletes run in the same queue as saves, so an
  in-progress save can't bring data back, and tabs you still have open aren't
  quietly saved again afterwards.
- **Pausing really pauses.** Pages you open while recording is paused are never
  saved, not even after you resume.
- **It's small, readable, and tested.** A few short, commented files, unit tests
  for every privacy and data-safety rule, and an end-to-end suite that runs the
  real extension in a real browser.

## What it stores

One record per link: its address (origin + path by default), its title, and
when you first and last saw it. Records are kept in the browser's local storage
on this device, up to 5,000 links by default; the links you saw longest ago are
removed first. Only `http`/`https` pages are recorded. Full details are in
[PRIVACY.md](PRIVACY.md).

## How recording, pausing, and deleting behave

- LinkTrail checks your open tabs every few minutes and shortly after a tab
  navigates, and saves each page it hasn't seen (or updates when it last saw it).
- **Pause** (the popup's *Recording* toggle) stops all recording. When you
  resume, tabs that are open at that moment are skipped until you navigate in
  them, so nothing you opened during the pause is saved.
- **Delete all data** removes every saved link. Tabs that are still open are
  skipped in the same way, so the deleted pages don't immediately reappear.
  Navigating to a new page in such a tab is recorded normally.
- Both rules survive a browser restart (restored tabs at the same address stay
  skipped).

## Browser support

The JavaScript is browser-agnostic (`browser.js` selects the right API), so the
same code runs across browsers. `npm run build` produces a folder per target:

| Browser | Folder | Install (developer mode) |
|---|---|---|
| Chrome, Edge, Brave, Opera, Vivaldi | `dist/chrome` | `chrome://extensions` → enable Developer mode → **Load unpacked** |
| Firefox | `dist/firefox` | `about:debugging` → This Firefox → **Load Temporary Add-on** → pick `manifest.json` |
| Safari | from `dist/chrome` | `xcrun safari-web-extension-converter dist/chrome` (requires macOS + Xcode) |

Chromium browsers are the primary target; the Firefox and Safari builds share the
same code and should be smoke-tested in those browsers before publishing.

To publish to the web stores and ship updates, see [PUBLISHING.md](PUBLISHING.md).

## Files

- `manifest.json`: base (Chromium) MV3 manifest; the build derives other targets
- `browser.js`: cross-browser WebExtension API handle
- `background.js`: worker that owns every write: snapshots, privacy cleanup, migration, delete
- `links.js`: the link-record data model and the pause/delete rules (pure, unit-tested)
- `privacy.js`: URL redaction, title and domain rules (pure, unit-tested)
- `config.js`: settings with defaults and validation
- `storage.js`: bucketed storage (256 entries, so a save touches a tiny fraction of the history) plus the write queue that serializes every change
- `ui.js`: shared popup/options helpers (delete request, two-click confirm)
- `popup.html` / `popup.js`: search and reopen, recording toggle, export, delete
- `options.html` / `options.js`: all settings and privacy controls
- `icons/`: generated by `scripts/make-icons.cjs`
- `scripts/build.cjs`: per-browser build into `dist/`
- `tests/*.test.js`: `node:test` unit suites for privacy, config, links, and storage
- `tests/e2e/`: end-to-end suite driving the built extension in a real browser over the DevTools Protocol
- `.github/workflows/ci.yml`: lint, unit tests (Node 22 and 24), and the end-to-end suite on every push and pull request

## Configuration

Defaults live in `config.js`; override them from the Options page. Every value
is validated and clamped, so a blank or out-of-range field falls back to a safe
value instead of breaking anything.

| Setting | Default | Range | Meaning |
|---|---|---|---|
| `captureEnabled` | true | | master on/off switch (popup "Recording" toggle) |
| `captureEvents` | true | | also record shortly after a tab navigates |
| `snapshotMinutes` | 5 | 1–1440 | how often open tabs are checked |
| `eventDelayMs` | 2000 | 0–20000 | wait after tab activity, then record once |
| `maxLinks` | 5000 | 100–50000 | links kept before the oldest-seen are removed |
| `storeFullUrl` | false | | keep query strings and fragments |
| `storeTitles` | true | | keep page titles |
| `excludedDomains` | [] | | sites never recorded (subdomains included) |

## Upgrading

Data from every earlier version (TabJournal 1.0–1.2 and LinkTrail 1.3) is
converted automatically on update. The current privacy settings are applied
during the conversion, so old full addresses get their query strings removed,
and the old storage keys are deleted. See [CHANGELOG.md](CHANGELOG.md).

## Development

- `npm test`: ESLint plus the `node:test` unit suites
- `npm run test:e2e`: builds, then runs the end-to-end suite in a real browser.
  Branded Google Chrome no longer loads extensions from the command line, so
  this uses Microsoft Edge if installed, or the browser in `LINKTRAIL_BROWSER`
  (Chrome for Testing or Chromium).
- `npm run build`: produce per-browser folders in `dist/` (updated in place)
- `npm run icons`: regenerate the PNG icons

### Troubleshooting

- **Changes don't show up / old behavior persists:** browsers don't reload an
  unpacked extension when its files change. After `npm run build`, click
  **Reload** on LinkTrail in `chrome://extensions`. The popup header shows the
  running version.
- **Pages reappear after "Delete all data":** fixed in 1.4. On older versions,
  tabs that were still open were saved again on the next check.
